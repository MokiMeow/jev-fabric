# Pack selection

Use the smallest question that can change a safe next step.

- `route`: select one declared path from a closed set, such as the owning code area after deterministic file search.
- `screen`: evaluate stated eligibility criteria before a human-approved workflow continues.
- `rank`: order already-validated candidates; do not create or mutate them.
- `verify`: judge whether supplied evidence supports a stated claim, retaining the evidence links and freshness.
- `risk`: triage an explicitly bounded risk; security approval, remediation, and disclosure stay outside the pack.
- `progress`: classify the next known state for a tracked workflow.
- `completion`: assess a declared completion condition against an immutable checklist.

Examples: route a local code issue to a known owner; screen browser-test failures for retry eligibility; rank precomputed test-fix hypotheses; verify CI evidence; triage a fintech exception for human review; assess a support workflow's next state; or check whether a release checklist is complete. In every case, record receipts and hand the result to the host model for explanation or follow-up reasoning.

Set a finite call, token, money, queue, and deadline budget. Use cache only when its key includes the material policy, provider/model, question, and freshness window. Batch only identical policy, provider, and state. Abstain when the evidence is stale, contradictory, missing, out of the declared options, or below the predeclared threshold.
